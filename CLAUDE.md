# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"אן" (Anne) — a Hebrew-language pre-triage assistant. Stage 1 is the RAG retrieval pipeline: `chunking → embeddings → Chroma vector store → semantic search`. Stage 2 (implemented, in `crew/`) is the CrewAI agent team on top of it: Anne (single visible persona/voice), four specialist doctors behind the scenes, a hierarchical routing manager, and a safety agent (Dr. Dexter) that gates every conversation turn. An anonymous turn log (`storage/`) records every turn for analytics — over local SQLite or the project's Supabase Postgres, one API either way; a Streamlit dashboard (`dashboard/`) and an educational ML prediction demo (`ml/`) sit on top of it. A computer-vision layer (`vision/`) turns an attached photo into anamnesis context (quality, deterministic measurements, a describe-only model call). A FastAPI wrapper (`server/`) serves the browser chat UI and the admin area (`web/`). Documentation, data, and code comments are in Hebrew.

> Educational project. Content is first-aid reference only, not medical advice.

## Environment

- **Python 3.12**, run via the conda env `anne_env`. The interpreter used in practice is `/Users/maordahan/anaconda3/envs/anne_env/bin/python3.12` — prefer it over a bare `python` to avoid hitting a `python3.14` build (stale `.pyc` files for 3.14 exist in `rag/__pycache__/`).
- **`numpy<2` is a hard constraint.** The macOS/x86_64 `torch` wheel is built against NumPy 1.x; NumPy 2 breaks torch with "Failed to initialize NumPy". `crewai` is pinned to `1.6.1` specifically because newer versions transitively pull `numpy>=2` or conflicting `tokenizers`, which would break the RAG stack and force an index rebuild. Do not bump these pins casually — see the rationale comments in `llm_requirements.txt`.
- Dependencies file is intentionally named `llm_requirements.txt` (not `requirements.txt`).
- The Supabase log backend adds `SQLAlchemy>=2,<3` and `psycopg[binary]>=3.1,<4`. Both are pure additions: no numpy dependency (numpy stayed 1.26.4 after installing), wheels for macOS and Windows (the `[binary]` extra bundles libpq, so nothing is compiled and no local postgres is needed — that is why not `psycopg2`), and both are imported **lazily inside functions**, so an environment without them still runs on SQLite.

## Architecture

The pipeline is three layers, all parameterized from one config module:

- **`rag/config.py`** — single source of truth for paths, collection name, embedding model, chunk sizes, and `DEFAULT_TOP_K`. Tune here, not inline.
- **`rag/chunking.py`** — splits each `data/<topic>/*.md` into one chunk per `##` section (תסמינים / טיפול ראשוני / המשך טיפול / פנייה מיידית). Over-long sections are greedily packed into ~600-char chunks with ~70-char overlap, splitting on line boundaries (the data is bullet lists) and falling back to sentence boundaries only for very long lines. The `---` footer (which holds the `מקור:` line) is stripped before sectioning but its source line is extracted into metadata. `load_chunks()` walks `data/`, using each **subdirectory name as the `topic` tag**.
- **`rag/embedding_store.py`** — `Embedder` wraps `intfloat/multilingual-e5-large` (local, multilingual, good for Hebrew, no API key). **The e5 model requires prefixes**: `"passage: "` for documents, `"query: "` for queries — applied automatically in `embed_passages`/`embed_query`. `VectorStore` is a thin wrapper over a Chroma `PersistentClient` (cosine space). `build_index()` runs the full pipeline and **resets the collection by default** (`reset=True` deletes `chroma_db/`). `search()` embeds a query and returns the nearest chunks, optionally filtered by `topic` via Chroma's `where`.

Data model: each chunk carries metadata `{topic, section, source, title, source_file}`, enabling both topic-scoped filtering and source citation.

### Agents layer (`crew/`, Stage 2)

Per-turn pipeline (`crew/pipeline.py :: ChatSession.run_turn`): **(safety gate ∥ Anne decides, in parallel) → specialist consult (direct fast-path or hierarchical fallback) → Anne composes**. Key decisions, all grounded in the *installed* crewai 1.6.1 source (do not trust docs/memory of other versions):

- **Structured output in ONE LLM call** (`parse_structured_output`, `_structured_kickoff`): passing `response_format=` to `kickoff` makes crewai 1.6.1 run the agent and then *always* run `Converter.to_pydantic` — a second LLM call that only re-formats the same output (no `json.loads` fast path; verified in `crewai/lite_agent.py::_execute_core` + `utilities/converter.py`). Measured in `anne_log.db`: a turn with only gate+triage logged 4 calls for 2 stages. So the pipeline now injects the schema into the prompt itself and parses the reply in code; **on parse failure it falls back to that same crewai Converter**, i.e. the new path is never worse than the old one, just cheaper when the model returns valid JSON. `TurnResult.structured_retries` counts fallbacks per turn (0 = fast path held; a persistent non-zero means the prompt or the model needs attention). Live measured on the same scenario: **7 → 4 calls per turn, 0 retries**, gate −32% and triage −40%.
  - Two traps this cost a live run to learn, both now regression-checked. (1) **Never inject `model_json_schema()` raw**: the model imitated the schema envelope and returned `{"description":…, "properties":{…the values…}}`, which fails validation, so *every* stage fell back to the converter — erasing the whole saving. `_schema_instruction` therefore prints field names + descriptions + an explicit skeleton and forbids `properties`/`description`; `parse_structured_output` also unwraps a `properties` echo as a belt. (2) The instruction targets the "**final answer**" (mirroring crewai's own i18n slice) rather than demanding "JSON only", because Dexter has tools: a bare-JSON reply can trip crewai's ReAct parser (`Failed to parse LLM output`) and burn an iteration — the opposite of the goal.
- **Streaming the compose stage** (`crew/streaming.py`, `run_turn(..., on_progress=)`): `build_anne("compose", stream=True)` gives that one agent a streaming LLM, so the native OpenAI provider emits `LLMStreamChunkEvent` per delta while still returning the full text from `kickoff` (so `output.raw` and everything downstream are unchanged). A single module-level bus handler routes chunks to the sink registered for the *emitting LLM object* — matching on `from_agent` is impossible because `Agent.kickoff()` builds a fresh LiteAgent per call. `on_progress` also receives `{"type":"stage"}` events (`gate_triage`/`consult`/`compose`). All of it is a display pipe: `on_progress=None` (CLI, tests) behaves exactly as before, and a raising consumer is swallowed (`_notify`) so a disconnected browser can never break a turn.

- **Anne runs outside the crew** via `Agent.kickoff()` (LiteAgent). In crewai 1.6.1 hierarchical process the manager executes every task itself (task.agent only scopes delegation), so putting Anne in the crew would make the manager the final voice. Two internal Agent instances (`build_anne("triage"|"compose")`) share one persona.
- **Parallel stage 1+2**: the safety gate (Dexter) and Anne's triage decision run concurrently in a per-turn `ThreadPoolExecutor` (both are I/O-bound LLM calls). Both only *read* `self.history`; `_commit` writes after both complete — no shared-state race. Dexter's emergency verdict always wins: on `is_emergency` the triage result is discarded.
- **Direct routing (fast path, most turns)**: when Anne's `topic_hint` is one of the four topics, the pipeline skips the hierarchical crew and runs that topic's specialist directly via `Agent.kickoff(prompt, response_format=SpecialistAdvice)` (graceful `pydantic=None` on conversion failure → fixed safe reply). Direct specialists (`build_specialist(..., with_tools=False)`) are **tool-less by design**: the RAG chunks and weather context are injected deterministically into the prompt by the pipeline (see below), so the consult is a single structured call with no ReAct loop — verified across live runs to be the fast *and* stable path (the economical model's tool loop intermittently skipped searches or burned all iterations to parse failures). Built lazily per topic and cached on the session (`_direct_specialists`); closed illustration catalog and closed-list validation hold here too. A deterministic **topic-hint safety net** (`_infer_topic_hint`, conservative keyword lexicon) fills a missing or `other` hint only when exactly one topic matches — a verified live failure had Anne classifying an obvious cold case as `other`, dropping the turn to the slow manager path; an explicit hint for one of the four topics is never overridden.
- **Care crew (fallback only when `topic_hint` is missing or `other`)** (`crew/crew.py`): 4 specialists + `manager_llm` (economical, temp 0.1), one consult Task with `agent=None` (manager may delegate to any doctor) and `output_pydantic=SpecialistAdvice`. `output_pydantic` **raises** on final conversion failure in 1.6.1 — `_consult` wraps kickoff in try/except and the pipeline falls back to a fixed safe reply.
- **Safety gate**: Dr. Dexter (`build_safety`, strong model, temp 0.1) checks every turn *before* any treatment via `kickoff(..., response_format=SafetyVerdict)`; LiteAgent conversion failure is graceful (`pydantic=None`) and the pipeline continues cautiously. An emergency verdict with an empty referral gets a hardcoded fallback text (schema validator) — safety never depends on LLM phrasing. Self-harm → ער"ן 1201; referral text must spell out the hotline digits (101/1201).
- **"לחץ" is two different words, and the gate now knows it** (`crew/red_flags.py`). In Hebrew *לחץ* is both psychological stress and physical pressure, and *לב* appears in "הלב דופק מהר" of a plain panic attack — so keyword-level detection stopped anxiety conversations that were never dangerous. The fix is **added discrimination, never removed sensitivity**, in two layers: (1) Dexter's instruction now states the contextual rule — pressure/pain is a red flag when tied to the chest or heart, or accompanied by radiation to arm/jaw/shoulder, cold sweat, nausea, pallor or shortness of breath — with the five negative examples spelled out (לחץ בעבודה · לחוץ לפני ראיון · מתח · לחץ נפשי · לחץ חברתי) and an explicit "this adds precision and cancels no flag from the list above"; (2) `apply_cardiac_safety_net` in the pipeline, which may only **escalate**: if the message unambiguously describes chest pressure/pain and Dexter did *not* declare an emergency, the code raises the verdict (never the reverse, and it never touches a verdict Dexter already made). Sharpening a prompt can create a false negative — the far worse failure — so that direction is backed by deterministic code, not by wording.
  - The detector works **per sentence**, which is what makes it work at all: in "לב דופק, ידיים מזיעות… אין מחשבות רעות, רק לחץ גדול" the heart word and the pressure word live in different sentences and must not combine into a flag nobody described. Within a sentence: an explicit phrase (`לחץ בחזה`, `כבדות בחזה`…) or a pain word within **3 words** of a chest/heart word — a window calibrated so "כואב לי, בעיקר בחזה" fires while "הלב שלי דופק והראש כואב" does not — plus a radiation rule (pain + מקרין/הקרנה + יד/זרוע/לסת/כתף) for the classic presentation that never says "חזה". Negation is handled by a deliberately **short** list of unambiguous phrases ("אין לי כאב", "לא כואב"…): anything not on it counts as positive, because over-clever negation parsing is how you miss "לא הפסיק לכאוב לי בחזה". An offline check runs 12 real-emergency phrasings and 16 anxiety/stress phrasings in both directions, and a mutation to naive substring matching fails it loudly.
- **Emergency destinations by location and time** (`crew/emergency_referral.py` + `data/emergency_locations.json`, plan point 6 — no longer a skip). Dexter writes only the human paragraph; the destination list underneath is rendered **in code** from the local file, because a hallucinated hospital name, phone or "open now" is real-world harm, not a weak answer.
  - **No network during a turn.** The file is static and pre-geocoded; `crew/tools.py :: referral_tools()` was reduced to the clock alone (`locate_place` removed — with destinations local it had nothing left to serve, and leaving it allowed an HTTP call inside a turn). An offline check greps the module's *code* (not its docstrings) for `requests`/`geocode`/`http` and asserts the tool list.
  - **The data**: national numbers + 14 hospitals + **27 Terem branches + 23 Bikur Rofe branches**, each collected from that branch's own official page (name, city, address, phone, hours) with `source_url` per record. `hours.by_day` (sun…sat) is the engine's source of truth — `{open, close}` = open, `{closed: true}` = explicitly closed, **`null` = not published, which is "unknown" and never "closed"**; `close < open` is an overnight shift. `hours.raw_he` keeps the site's own wording for display, and `sun_thu`/`fri`/`sat` from the original TEMPLATE shape survive only where one range really covers the bucket. Where a site publishes the same weekday twice (Holon), the **narrower** window wins — never claim open on the wider one.
  - **Coordinates come only from `geocode_emergency_locations.py`** (the one-off script, using the existing `tools/location.py`), at **city resolution** — Open-Meteo's geocoder is a place database, so a street or a hospital name is not in it, and `_meta.geocoding` says so. 60/64 records resolved; 4 cities the service doesn't know (Katzrin ×2, Modi'in Illit, Beitar Illit) stay `null` rather than guessed, and simply don't enter distance ranking.
  - **The critical distinction, enforced in code**: `SafetyVerdict.referral_level` is `critical` | `urgent_care`, defaults to `critical` when missing (validator), and `escalate_level()` may only *raise* it — a conservative Hebrew lexicon over the red flags + the user's message forces `critical` for chest pain, stroke signs, breathing difficulty, unconsciousness, uncontrolled bleeding, anaphylaxis, poisoning, heatstroke and self-harm. `critical` → the file's `critical_prefix` (101) first and prominent, hospitals next, and each urgent-care section carries `urgent_care_not_suitable_note`; `urgent_care` → a lead line naming an urgent-care center as the destination and the ER as backup, with no 101 prefix.
  - **All three headings always render** (בתי חולים · ביקור רופא · טרם) with their `empty_text` when nothing qualifies — showing that every option was checked — and the health-fund numbers + `footer_note` always close the block. No known locality (or a broken/missing file) → `None`, and the fixed national text stands as before. The locality itself is remembered across turns (`ChatSession._locality`) and can also be recovered from the message by matching city names *in the file* (`detect_locality`), because on an emergency turn the triage result is discarded.
- **RAG warm-up (process-level)**: the first `ChatSession.__init__` in the process starts one daemon thread (`pipeline._start_rag_warmup_once()` → `crew/tools.py :: warm_up_rag()`) that pre-loads the e5 embedder (~2GB) and Chroma client behind a `threading.Lock`; later sessions in the same process reuse the loaded globals instead of spawning a thread each. A RAG call arriving mid-warm-up waits on the lock instead of double-loading.
- **`ChatSession(log_turns=False)`** — a conversation that is not written to the anonymous log. Used for demo runs (a scenario played to an audience is not real usage, and logging it distorts the dashboard and the ML demo). The flag sits on the *session*, not the turn, so it cannot be forgotten mid-conversation.
- **`ANNE_DIAG=1`** — an opt-in diagnostic print, inert by default and with zero effect on flow or output. It exists because three things are invisible when something "doesn't arrive" in an answer, and each print covers one: which tools ran in the turn and what they returned (weather/geocoding/RAG), the context strings **as they were actually injected** into the specialist prompt, and the history length at the start and end of each turn (is it accumulating between turns?). It prints conversation text, so it is a local debugging tool, not something to leave on.
- **Perf & tool metrics**: `TurnResult` carries `timings: dict[str, float]` (per-stage seconds: `safety_gate`, `triage`, `consult_direct`/`consult_crew`, `compose`, `total`), `llm_calls: int`, and `tool_usage: dict[str, int]` (per-turn counts from `crew/tools.py :: get_tool_usage()`; reset each turn, counted thread-safely). **`llm_calls` is counted at the source** via a global `LLMCallCompletedEvent` listener on crewai's event bus (`crew/metrics.py`), reset per turn — do NOT count from kickoff outputs: `LiteAgentOutput.usage_metrics` is a plain dict (attribute access silently yields 0) and the native `BaseLLM._token_usage` accumulates per LLM instance for its whole lifetime, not per turn (both bugs verified). `crew/main.py` prints all metrics when `ANNE_VERBOSE=1`.
- **Deterministic context injection** (code, not tool loops — verified far more reliable than the economical model's ReAct): *time* — the current time/date/weekday line (`pipeline._time_context_he()`) is injected into every prompt (gate, triage via `_triage_content_he`, both consult paths, compose); *weather* — Anne's triage extracts a mentioned locality into `AnneDecision.locality_he`, and the pipeline calls geocoding+weather in code (`_weather_context_he`, free Open-Meteo HTTP, recorded in the tool counters) and injects the line into consult prompts *and* compose (so the final reply mentions it even if the doctor didn't); *RAG* — on the direct path the pipeline retrieves the topic-locked chunks itself (`crew/tools.py :: deterministic_rag_context`, also counter-recorded) and injects them as `{rag_context}`, enforcing RAG-first in code. The LLM-facing tools remain available to the *crew-path* doctors as backup.
- **Source hygiene (faithfulness, two layers)**: (1) history served to agents strips `מקור:`/`מקורות:` lines from Anne's previous replies, and consult prompts require `sources` to be copied verbatim from the current turn's chunks — fixes a verified cross-turn contamination bug; (2) a `SpecialistAdvice` model validator (`schemas.py`) drops any source that matches no `מקור:` line under `data/` (lenient matching: URL containment / title containment, dash+case normalized — see `source_is_known`) and forces `sources=[]` on `topic=other` — fixes a verified invented-sources bug ("המרפאה לרפואת שיניים"). Dropped values are exposed via `pop_filtered_sources()` → `TurnResult.filtered_sources` (observability: distinguishes "didn't cite" from "cited garbage that was filtered").
- **Anne-never-treats guard (code layer)**: beyond the sharpened triage prompt, `run_turn` converts a `reply` decision to `consult` when the user message contains a medical-complaint marker AND the reply looks like treatment steps (≥2 non-question list lines, or ≥2 whole-word treatment imperatives) — `_looks_like_treatment_steps`/`_mentions_medical_complaint`, deliberately conservative so anamnesis questions pass through. Fixes the verified worst bug: on a mid-conversation topic switch (anxiety→cut) Anne wrote wound-care steps herself with no consult/RAG/sources.
- **Smalltalk guard**: a deterministic lexicon check in `run_turn` (`_is_smalltalk_only`) catches greeting-only messages that triage misroutes to consult and returns a fixed warm reply instead (verified bug: "שלום אן" got full anxiety treatment). The triage prompt also forbids consulting on messages with no medical content.
- **illustration_id** is coerced to `None` by a schema validator unless it exists in `illustrations/illustrations.json` (closed list; `crew/illustrations.py`). Each doctor is shown only its topic's category + "כללי" (`catalog_for_topic`, ~9 focused entries incl. `steps` summaries) and *required* to pick when a recommended action appears there. If the model still returns null, a deterministic fallback (`suggest_illustration`: unigram+bigram Hebrew stem matching of `advice_he` against the topic category's names/steps, clear-match threshold, never guesses) fills it in before compose — fixes a verified cold-topic regression where the doctor recommended saline rinse/steam yet returned null. `crew/main.py` renders the chosen illustration as a terminal block and opens the PNG (disable with `ANNE_NO_IMAGE_OPEN=1`).
  - **No repeated illustration inside one conversation** (`pipeline._pick_illustration`, the single place that decides the turn's illustration): the session remembers what it has already shown (`ChatSession._shown_illustrations`, per conversation), and an id that was already shown is replaced by an alternative from the *same topic category* — found by the same `suggest_illustration` matcher with an `exclude` set, so the alternative still has to genuinely match the advice. **No clear alternative → showing it again is allowed** (a correct illustration that repeats beats a different one that doesn't fit); that case is reported as `TurnResult.illustration_repeated=True`, which is what distinguishes "the rule didn't fire" from "there was nothing to swap to". The null-fallback path prefers an unseen illustration too. The prompt layer only *nudges* (`{shown_illustrations}` is injected into both consult paths, direct and crew) — enforcement is in code, like the time/weather injection. Live-verified on the cold scenario: the doctor proposed the same illustration in turns 2 and 3 and the pipeline swapped to `steam_inhalation` then `rest_and_fluids`.
- **Specialists**: the *direct-path* variant is tool-less (see above; `max_iter=3`, single structured call). The *crew-path* variant keeps the topic-locked RAG tool + context tools with `max_iter=8` — in crewai 1.6.1 every ReAct parse failure burns an iteration, and 5 proved too tight ("Maximum iterations reached" forces a lower-quality final answer). Context-tool policy there is a three-branch rule (`build_specialist`): injected weather context → weave it into `advice_he`, no tools; locality mentioned but no context → `locate_place`→`get_weather` (never without coordinates); no locality → never guess, never call. Anne's triage carries a mentioned locality into both `consult_query_he` and `locality_he`.
- **crewai 1.6.1 gotchas honored in code**: agent construction requires `OPENAI_API_KEY` to exist in env (no network call until run) — `ensure_api_key()` gives a Hebrew error; tools must return `str` and never raise (crewai silently re-runs failing tools 3×); clock/weather tools disable crewai's tool cache; task-description `{placeholders}` are interpolated by blind string replace, so user text is brace-sanitized in `_sanitize()` (also applied before `str.format` in the direct-consult prompt); specialist `role` names are short ASCII ("Dr. Wynds") because hierarchical delegation matches coworkers by role string; telemetry is disabled by default in `crew/__init__.py` (must be set before `import crewai`).

### Conversation log layer (`storage/`)

Anonymous per-turn logging — the data foundation for the dashboard and the prediction model. One row per turn in table `turns`, in **either of two backends**: local SQLite (`anne_log.db`, stdlib `sqlite3`, the default) or the project's Supabase Postgres. Path/target override: `db_path` param or `ANNE_LOG_DB` env var (SQLite files are gitignored via `anne_log*.db`).

- **The backend is a switch under the API, not a second API** (`storage/backend.py`). `ANNE_LOG_BACKEND=sqlite|supabase` (read from `.env` — the module calls `load_dotenv` itself, because `streamlit run` and `python -m storage.synthetic` don't). Every public function keeps its exact signature; each one resolves its target through the single `_target(db_path)` seam and dispatches. An offline check compares the parameter names of all eight functions to a fixed table, so a signature change fails loudly — `crew/pipeline.py`, `dashboard/` and `ml/` never learn which backend they're on.
- **`db_path` means "which dataset", not "which file".** A path (SQLite) or a table name from the closed list `turns`/`turns_synthetic` (Supabase), mapped both ways: a file whose name contains `synthetic` → `turns_synthetic`, and a table name handed to SQLite mode → that mode's file. That mapping is what lets the dashboard switch pick a **table** without touching the connection, and lets `ml/dataset.py`'s `DEFAULT_TRAIN_DB` (a synthetic *file* path) train off the synthetic *table* with no code change. The closed list is also the injection guard: a table name is an identifier and cannot be parameterized, so anything else falls back to the default with a warning.
- **Graceful fallback, sticky per process.** Missing settings, missing package (`SQLAlchemy`/`psycopg` are imported lazily *inside* functions) or a failed connection return the log to local SQLite with **one warning** via `logging.getLogger("anne.storage")` — never a print (it would land inside Anne's reply in the terminal) and never an exception. Sticky on the first failure by design: a 5-second timeout on every turn is worse than a declared local log, and the next process start retries. `describe_target()` therefore reports what is *actually* being used, and `dashboard/ui.py :: _probe_backend` turns that into an on-screen note — checked against the **requested** backend, not the effective one, or the note would flash once and vanish on the next Streamlit rerun.
  - The fallback resolves its file through the same `sqlite_path_for` as a normal target. First version mapped table→default file and ignored `ANNE_LOG_DB`, so the turn after a failure was written to a different file than the one being read — two code paths disagreeing. `turns` is treated exactly like `None` there.
- **`storage/pg_schema.py` is the only translation of the schema to Postgres**: `PG_COLUMNS` is an ordered dict whose keys must equal `COLUMN_NAMES` (`assert_matches_declared_schema` — a new log column breaks the offline check until it is consciously translated, the same guard shape as `ml/dataset.py`'s column classification). What genuinely differs is dialect: `INTEGER PRIMARY KEY AUTOINCREMENT` → `bigint generated always as identity` (so an explicit `id` insert is rejected — we never write one), SQLite `GLOB` → POSIX `~` regexes written with `[0-9]`/`[a-z]` classes and no backslashes (independent of `standard_conforming_strings`), `REAL` → `double precision`. The enum CHECKs are built from `TOPICS`/`CONSULT_PATHS`, not re-typed.
- **`storage/migrations/001_create_turns.sql` is generated, not hand-written** (`python -m storage.pg_schema --write`) and an offline check compares the committed file to `migration_sql()` byte-for-byte, so it cannot go stale. Run it once in Supabase → SQL Editor. It is idempotent (`create table if not exists` + `add column if not exists` per column + `create index if not exists`), and **security is part of creation**: RLS enabled with no policy + `revoke all … from anon` and `from authenticated` on both tables, so the public browser key can neither read nor write the log (the service role and the project's Postgres connection bypass RLS and keep working). `ensure_ready()` applies the same statements when *it* creates a table, so an auto-created table is never more exposed than a manually created one; the security statements run in their own transactions because a failed statement aborts a Postgres transaction, and `revoke … from anon` legitimately fails on a non-Supabase Postgres (no such role) — that deserves a warning, not a lost write.
- **The connection** (`storage/supabase_backend.py`): SQLAlchemy Core + psycopg 3 (`psycopg[binary]` — libpq ships in the wheel, so no compilation and no local postgres on macOS *or* Windows; neither package touches numpy, so the `numpy<2` pin is unaffected — verified, numpy stayed 1.26.4). No ORM: the SQL is ours, built in `pg_schema` with named parameters (`:ts_utc`), and the engine is cached per process (without it every turn would pay a fresh remote connect).
  - **The password is URL-encoded in code** (`normalize_db_url`). A Supabase-generated password may contain `@ / : # %` or a space, each of which breaks URL parsing — so the string is split **manually** (scheme, then the **last** `@`, then the first `:`), because `urlsplit` is exactly what fails on such a password before you get the chance to encode it. `quote(safe="")` on user and password, skipped when the value already contains `%XX` (or `%40` would become `%2540` and fail silently), plus `sslmode=require`/`connect_timeout=5` filled in. `safe_display_url` is the only form allowed into a log or the UI. An offline check round-trips a password with all of those characters through SQLAlchemy's own `make_url`.
  - **Direct (5432) vs Transaction pooler (6543)**, detected by port or `pooler.supabase.com` host, and it changes behavior rather than just documentation: pooler → `NullPool` + `prepare_threshold=None` (pgbouncer transaction mode breaks server-side prepared statements and a local pool over a remote pool is pointless); direct → small pool with `pool_pre_ping`. The pooler hostname carries the region and **cannot be derived** from the direct one, so automatic failover requires pasting `SUPABASE_DB_URL_POOLER` too; switching for good is just replacing `SUPABASE_DB_URL` (documented in README).
  - **`SUPABASE_URL`/`SUPABASE_SERVICE_KEY` are declared in `.env` but not used by this layer** — it speaks Postgres directly, not REST. Saying so beats pretending the key is in play; they are the project identity (e.g. for reaching the project through the Supabase console), not keys this layer consumes.
- **Testing is offline and free, always** (`run_log_backend_checks`, 11 checks): all SQL goes through a two-method connection seam (`execute`/`execute_many`), so `set_connection_factory` injects an in-memory fake Postgres and **no network call happens in any test** — what gets verified is ours (26-column mapping identical to `scrub_record`'s output, the INSERT column list, table routing, the DDL, both fallback paths with their warnings, no password in any message, and one real `AppTest` run of the dashboard in the "Supabase configured but unreachable" state). `run_offline()` forces `ANNE_LOG_BACKEND=sqlite` at its very top (before any import that might `load_dotenv`) so a developer `.env` pointed at Supabase can never make the free suite touch the cloud. Mutation-tested: dropping the password encoding, reordering `PG_COLUMNS`, removing the RLS statements, removing the table-name whitelist and ignoring the resolved target each fail exactly the intended check, and a schema mismatch is reported as a failed check instead of a traceback.
- **`write_records()`** (new, additive) writes many scrubbed records in one transaction — used by the synthetic generator, which previously opened a connection per row (500 remote round trips for one seeding run). `write_record()` is unchanged and still strict.
- One consequence worth knowing: in Supabase mode the per-turn write is a network round trip (~100ms) inside `_finish` instead of a sub-millisecond local INSERT. It is still best-effort and still cannot fail a turn.

- **Privacy by design, three enforcement layers.** (1) The schema has zero free-text columns: user/Anne text is stored as lengths only (`user_message_chars`/`reply_chars`), red flags and sources as counts, and per-tool counters map to fixed columns (`TOOL_COLUMNS`; an unknown tool name folds into `tools_other` without storing the name). The only TEXT columns are strict-pattern IDs or closed vocabularies: `ts_utc`, `session_id`, `consult_path`, `topic`, `illustration_id`. (2) `scrub_record()` validates every column before any write — free text in an enum/slug field drops to its safe default; an invalid identity field (`ts_utc`/`session_id`/`turn_index`) rejects the whole record; unknown keys are discarded. (3) SQL CHECK constraints reject free text even on direct writes (IntegrityError). **Do not add free-text columns** — the privacy guarantee is structural, not policy.
- **Schema version 2 adds one column: `image_attached`** (0/1 — did the turn include a user-attached photo; from `TurnResult.image_used`). It is a flag *about* the turn, not data *from* the image, so the structural privacy guarantee is unchanged. Because `CREATE TABLE IF NOT EXISTS` never touches an existing table, `init_db` now also runs `_migrate()`: it compares `PRAGMA table_info(turns)` to the declared `COLUMNS` and `ALTER TABLE ADD COLUMN`s whatever is missing (idempotent, cheap). Two consequences that are deliberate: a new column must carry `DEFAULT` when it is `NOT NULL` (SQLite's ADD COLUMN rule), and new columns are declared **last** so a migrated file and a fresh file have the same column order. Old rows keep `schema_version = 1` and get `image_attached = 0` — factually correct, those turns had no photo. An offline check builds a pre-migration table, migrates it, and asserts the column order, the old row's values, and that the CHECK constraint holds on the ALTER-added column too.
- `session_id` is a random `uuid4().hex` minted per `ChatSession` — groups the turns of one conversation with no link to the user. `consult_path` (`none`/`direct`/`crew`) records the consult route *attempted* (derived from timing keys), while `consulted` records success — distinguishing "no consult" from "consult failed → failsafe".
- API (`storage/turn_log.py`): `init_db()` (idempotent create), `log_turn(result, ...)` (pipeline entry — best-effort, swallows everything, returns bool), `write_record()` (strict, raises; always scrubs — used by tests/synthetic), `reset_log()` (admin wipe + VACUUM, returns deleted count), `fetch_turns()`.
- Pipeline hook: `run_turn`'s `_finish` closure calls `pipeline._log_turn_safe` on **every** exit path (emergency, reply, smalltalk, failsafe, full consult). The import is lazy and double-wrapped in try/except — a missing/broken storage layer never touches the reply or the flow (verified by an offline check). The write is a single sub-millisecond INSERT; agent behavior is untouched.
- Synthetic data: `python -m storage.synthetic` (defaults: 200 turns, seed 7, separate `anne_log_synthetic.db`) generates realistic distributions through the same scrub+CHECK path — real illustration ids, `other`→crew routing, rare emergencies.
- Offline checks (slide 17 in `test_anne_suite.py --offline`): live schema == declared `COLUMN_NAMES`, TEXT-column whitelist, TurnResult→row mapping, PII scrub, DB-level CHECK guard, reset, and hook resilience with a broken DB path.

### Analytics dashboard + ML page (`dashboard/`) — two apps, one UI layer

**Two separate Streamlit apps** over the same turn log (free, no LLM), on two ports:

```bash
streamlit run dashboard/app.py                        # overview → :8501
streamlit run dashboard/ml_app.py --server.port 8502  # ML page  → :8502
```

Requires `streamlit`/`pandas` (in `llm_requirements.txt`; verified compatible with the `numpy<2`/torch/crewai pins — numpy stays 1.26.4). They were one app with two tabs; the split means the ML page can be demoed, deployed and restarted on its own, and the admin cards probe each port independently.

- **Privileged actions are locked by default** (`dashboard/admin_access.py` — policy — + `ui.py :: admin_gate` — the only rendering). Both apps are deployed as **public** Streamlit apps, and the reset button calls `reset_log`, which in Supabase mode deletes the cloud table: without a gate, an anonymous visitor could wipe the project's data from the browser. The rule is **locked by default**, and the two mutating actions (reset in `app.py :: _admin_reset`, train+save in `ml_app.py`) are the only ones — verified by audit: `write_record`/`write_records`/`log_turn` are not imported anywhere under `dashboard/`, and everything else (cache refresh, CSV export, filters) is read-only. `init_db()` in `_probe_backend` stays ungated on purpose: it is idempotent DDL required for *reading* in Supabase mode, never a data mutation.
  - **No environment guessing.** There is deliberately no "am I running locally" heuristic: such a guess fails *open* the day its signal changes, and `Host` is client-supplied and forgeable. Authorization rests on one thing that exists locally and not in the cloud — `ANNE_DASHBOARD_ADMIN_CODE` in `.env`, which is gitignored and therefore simply absent from the public container. No code → `available=False` → **the control is never created** (not a disabled button, not an expander hiding it; a destructive action that exists but is "hidden" is still in the page). Same design decision as the server's admin area, one source of secrets at one scope.
  - `ANNE_PUBLIC_DEPLOY=1` (and the `/mount/src` Streamlit Cloud checkout path) is a **belt that can only close**: privileged actions stay absent even if a code was pasted into the deployment's secrets by mistake, and that case logs one warning. A code shorter than `MIN_CODE_LENGTH` (8) is treated as a *misconfiguration*, not a wrong code — action absent, with a Hebrew notice shown **only** when the run isn't public (in public it would advertise that an admin area exists).
  - The code is normalized before comparison and compared **as bytes** — and the order matters: Cf characters are stripped *before* `strip()`, because a real RTL paste is `"<RLM> <code> <LRM>"` and `strip()` stops on the non-whitespace RLM, leaving the space inside the value. The reverse order was written first and the paste test is what caught it. `compare_digest` on *str* raises on any non-ASCII character, so a Hebrew code would have crashed the page instead of failing as "wrong code" (the same lesson as `server/app.py`).
  - Nine offline checks (slide 18, plan 15+18): the policy layer directly (no code / public-with-code / correct / wrong / too-short / bidi+Hebrew), that the policy module imports no streamlit, and real `AppTest` runs of **both** apps in all three states. The public one asserts a **closed whitelist** of rendered buttons, so any *new* button appearing in public mode fails the check until consciously classified. Mutation-tested: removing the public lockout fails 2 checks, an always-open gate fails 5.
- **Four files by design**: `data.py` is pure pandas (load/filter/KPIs/aggregations, no streamlit import) so the offline suite tests it without a server; `ui.py` is the **shared view layer** (palette, brand CSS, `page_setup`, `brand_header`, `chart_note`, `category_bar`, cached load, DB picker, filters, sidebar cross-link, footer) — imported by both apps and duplicated by neither; `app.py` and `ml_app.py` are page content only. Keep new analytics in `data.py` and anything visual that both pages could want in `ui.py`. An offline check fails if either app re-defines a shared function (`def category_bar(` etc.) or if the dashboard grows an `ml` import again.
- **Each app runs `streamlit run` directly**, so `sys.path` gets `dashboard/`, not the project root — both files keep the 4-line `PROJECT_ROOT` bootstrap *before* importing `dashboard.*`/`storage.*`. Don't "clean it up".
- **`dashboard/app.py`** (overview): KPI row, daily trend with emergency dots, topic/path/stage/tool/illustration bars, session-length histogram, table + CSV, and the admin reset button. Every category chart is guarded with an "empty in this filter" caption — a degenerate filter (e.g. emergency-only, where turns stop before a topic/illustration is ever assigned) must never reach a chart builder.
- **`dashboard/ml_app.py`** (the teaching page), in this order: branded header + non-clinical warning → what the model predicts (task framing, 4 features / binary classification) → train-all button → a card per model (plain-Hebrew explanation + its metrics + a "🧮 המתמטיקה" expander with `st.latex` formulas and a Hebrew note per formula) → model comparison (ROC-AUC bars + full metrics table) → a metric glossary expander (and why plain accuracy is absent at ~4% prevalence) → model selector → "what does this model look at" (odds ratios / feature importances) → interactive what-if that scores **all** models on the same input → strip plot vs. actual outcome → the proxy-leakage caveat expander. The ML import is a soft dependency (module-level try → `ML_AVAILABLE`); the page degrades gracefully: no sklearn → deps message, no trained model → train hint + button, Hebrew ValueError (e.g. single-class log) → `st.error`, empty log/filter → the teaching content still renders and only the strip plot is replaced by a caption. Strip-plot colors: routine=MUTED, emergency=EMERGENCY (the reserved red); per-model colors are fixed by key in `MODEL_COLORS` with the baseline deliberately in muted sand.
- **`category_bar(frame, …, key_col="label")` raises a named `KeyError`** when the display column is missing, instead of failing deep inside Vega. That is the fix-shape of a real crash: `illustration_counts` was changed to emit Hebrew names and the display column moved, which took down `_render_overview` — and with it the ML tab, since both were one app. The contract is now locked by an offline regression check: *every* aggregation in `data.py` returns a `label` column (on full data, on a degenerate emergency-only filter, and on an empty frame), each result actually compiles through `category_bar`, and both apps are run end-to-end via `AppTest` in all three data states.
- **`_load_bundle` is `@st.cache_resource`** keyed by model path + mtime: without it every slider move re-read ~0.6MB of joblib from disk (~140ms measured) in the most interactive part of the page. The train button calls `_load_bundle.clear()` so a freshly trained model is picked up. It lives in `ml_app.py` — it is the one cached object that is *not* shared.
- **Sliders and progress bars are forced to `direction: ltr`** (reported bug): BaseWeb builds the slider track from flex parts and positions the thumb by percentage-from-left; under the page's `direction: rtl` the parts mirror while the thumb doesn't, so the handle stops matching the gauge (a 0→100% progress bar fills from the wrong side for the same reason). The numeric axis is LTR in every language; the Hebrew label stays RTL and right-aligned. The what-if section additionally echoes the exact values used for the prediction, so the input can never be ambiguous.
- **UI** (all of it in `ui.py`, so the two apps cannot drift apart): RTL + brand CSS injection (`inject_brand_css`: Streamlit is LTR and visually neutral) using the same `assets/colors.css` tokens as the chat and admin area — KPI tiles as soft white cards, a coral rule under every section title, the model card and the chart-note card. Branding: `assets/Logo.png` as the favicon, in `st.logo` (sidebar, incl. collapsed) and in `brand_header`; `assets/Logo_2.png` as the decorative figure at the bottom of the sidebar. Anne brand theme in `.streamlit/config.toml` (also disables Streamlit telemetry, matching the crewai-telemetry-off policy). Sidebar, in call order: the **data-source switch** → date/topic/path/emergency filters → [dashboard only] the **admin area**, which exists at all only when `admin_gate` reports `unlocked` (see the locked-by-default section above): reset button gated by a confirmation checkbox (`disabled=not confirmed`) → `reset_log(db_path)` → `st.cache_data.clear()` → success message via `session_state` across the rerun → a cross-link to the sibling app (its URL *and* its run command, because a link to an app that isn't running is a dead end) → the figure + disclaimer.
- **The data source is a two-state switch, not a dropdown** (`sidebar_data_source` in `ui.py`, so both apps get the same control in the same place with the same labels): `st.segmented_control` with exactly two options — "נתונים חיים" / "נתונים סינתטיים" — because there are exactly two states and the active one should be readable without opening a menu. `db_choices()` maps each label to a real target — in Supabase mode the two tables (`turns` / `turns_synthetic`, so the switch changes table and never the connection), and in SQLite mode a real file: the first match from `db_options()` **in that category** (`ANNE_LOG_DB` is checked first and therefore wins, but only for its own category — a file whose name contains `synthetic` is the synthetic one), falling back to that state's default path. A state whose file does not exist yet is still selectable: it is created empty on read and the existing "אין עדיין רשומות" notice renders as before (verified per app under AppTest, in both directions). `required=True` blocks deselection (which would return `None` and leave the page with no data source at all). The active segment is coral **`BRAND_STRONG` (#B34A32)**, not `BRAND` — white text on coral-400 is 2.48:1.
- **Every chart carries a `chart_note` above it** — 2–3 sentences on what the chart type shows and how the metric is defined, deliberately *never* a conclusion about the current numbers (they change with every filter and every new conversation, so a hardcoded reading would go stale or simply lie).
- **Label legibility** (reported bug, two rounds — Hebrew y-axis labels first truncated to "…", then reduced to a single visible letter). `category_bar` now stops depending on Vega's automatic axis-label sizing, and every one of these matters:
  - `labelLimit=LABEL_LIMIT_PX` (260) — **finite on purpose**. The default 180px truncates with "…", but `0` is a trap: in some Vega layout paths the label area is derived *from* `labelLimit`, so 0 means zero area and the text is pushed outside the SVG, leaving one glyph visible.
  - **Explicit pixel height** (`rows * ROW_HEIGHT_PX + 46`), never `alt.Step`: `_prepare_vega_lite_spec` in Streamlit injects `autosize={"type":"fit","contains":"padding"}`, and Vega-Lite does not support `fit` when the size is step-derived.

  - 18% headroom on the value scale (the end-of-bar value label) and explicit `labelAngle=0`.
  - CSS forces the chart container to `direction: ltr` with `overflow: visible` — Vega lays out the y-axis on the left with no knowledge of page direction, and an RTL container clips exactly that gutter.
  - The six category charts each get a **full-width row** (they were two-up), and the illustration chart shows Hebrew names from the closed catalog (`data.illustration_names()` reads `illustrations/illustrations.json` directly — the dashboard stays free of any `crew`/crewai import) instead of raw snake_case ids.
  - Offline checks assert all of the above per compiled spec, plus the LTR/overflow CSS. Note the AppTest check earns its keep here: a single-brace CSS block inside the f-string in `inject_brand_css` broke the whole page and was caught before shipping — when editing that CSS, remember every literal `{`/`}` must be doubled.
- **Charts** (Altair, ships with streamlit): KPI tiles, daily trend with emergency dots, topic/path/stage/tool/illustration bars, session-length histogram, full table view + CSV export. Identity is always redundant to color (axis labels + direct value labels).

- Offline checks (slide 17): data-layer aggregation consistency on synthetic data, empty-log handling, reset-button wiring, and a full server-side run via `streamlit.testing.v1.AppTest` (no browser, fails on any script exception).

### ML prediction demo (`ml/`)

**Educational ML capability demo ONLY — not a clinical tool.** Trained on synthetic data with a tiny positive sample; never present its metrics as clinical accuracy. Predicts P(the turn ends in an ER referral) — target is the `emergency` column (Dexter's verdict; there is no `referred_to_er` column, that's the concept name). scikit-learn + joblib (both transitive deps of sentence-transformers, declared explicitly; verified against the `numpy<2` pins).

- **Four files by design**: `dataset.py` (load via `storage.fetch_turns` → pandas, feature build), `models.py` (the closed model registry + the educational metadata), `train.py` (train/evaluate/save, entry point `python -m ml.train`), `predict.py` (load + `predict_er_probability(record) -> float in [0,1]` and batch `predict_frame(df) -> ndarray`, demo entry `python -m ml.predict`). `ml/__init__.py` re-exports lazily (PEP 562) on purpose — eager submodule imports fight `python -m ml.train` (runpy double-import warning). Model path resolution mirrors `ANNE_LOG_DB`: explicit param > `ANNE_ML_MODEL` env var > `ml/models/er_referral.joblib` (`resolve_model_path`) — the env var is how the offline suite pins the dashboard tab to a temp/absent model.
- **Four models, one task, one split** (`ml/models.py :: MODEL_SPECS`): logistic regression (the default — the transparent one), random forest, gradient boosting, and a non-learning baseline (`DummyClassifier(strategy="prior")`) whose ROC-AUC is exactly 0.5 and exists as the reference line. All four share the same `build_preprocessor()` and — critically — `train_all_models` splits **once** and hands the identical train/test indices to every model, otherwise the comparison is meaningless (an offline check asserts the split signature is identical across models). Gradient boosting has no `class_weight`, so it gets balanced `sample_weight` at fit time via `fit_kwargs_for` — same intent, different mechanism. No new dependency: all four ship inside scikit-learn.
- **`MODEL_SPECS` is the single source of truth for both code and teaching**: builder, plus `name_he`/`family_he`/`explanation_he`/`formulas` (LaTeX, rendered with `st.latex`)/`math_notes_he`/`interpretation`. An offline check fails if a model is added without full documentation — the page's educational promise is enforced, not hoped for. `feature_contributions()` returns odds ratios (`exp(coef_)`) for linear models and `feature_importances_` for trees; `encoded_feature_names()` maps post-one-hot columns to Hebrew names so the interpretation chart describes what the model actually saw.
- **Bundle format is backward compatible**: `pipeline`/`features`/`target`/`metrics`/`sklearn_version` still describe the default model, and the new `models` dict adds every trained model with its metrics, feature names and contributions. `available_models(bundle)` and `_pipeline_for(bundle, model_key)` handle both formats, so an old single-model file still loads and renders (covered by an explicit legacy-bundle check). `predict_er_probability`/`predict_frame` take an optional `model_key`; an unknown key raises a Hebrew `ValueError`.
- **Honest caveat surfaced on the page, not hidden**: the strongest feature is invariably "no topic", because an emergency turn is stopped by the safety gate *before* a specialist assigns a topic — so `topic` is partly a consequence of the outcome (proxy leakage) even though it passes the formal "known at turn start" rule. The page explains this in an expander as a teaching example, and it's the first thing to revisit if this demo is ever taken further (drop `topic`, or use Anne's pre-consult `topic_hint`).
- **A fourth classification group: `NON_FEATURE_COLUMNS`.** `image_attached` is knowable at turn start and therefore *not* leaky — it was still deliberately left out of the model, because in the synthetic data it is constant 0 and would enter as a dead column: a zero coefficient in the interpretation chart, a meaningless fifth what-if control, a row in the importance table that teaches nothing. `ml/dataset.py` documents the three-line change that promotes it once real data with photos accumulates — and the leakage question to re-ask then (if users attach photos mainly when things look bad, the flag encodes severity, exactly like the documented "no topic" trap).
- **No target leakage, enforced**: features are only fields knowable at turn start — `topic` (None→"unknown"), `turn_index`, `user_message_chars`, cyclic hour (sin/cos from `ts_utc`). Everything downstream of the emergency verdict (`red_flags_count`, consult path/success, timings, tool counters, reply length…) is listed in `LEAKY_COLUMNS` and excluded. The offline check requires every schema column to be classified into exactly one of feature-source/identity/target/leaky/non-feature — adding a log column breaks the check until consciously classified in `ml/dataset.py`.
- **Model**: sklearn Pipeline — OneHotEncoder(topic) + median-impute+scale numerics → LogisticRegression `class_weight="balanced"` (emergencies ~4%). Balanced weighting inflates absolute probabilities (the demo prints a calibration note); ranking is the meaningful output. Saved with joblib as one bundle `{pipeline, features, target, metrics, sklearn_version}` to `ml/models/er_referral.joblib` (gitignored — rebuild with `python -m ml.train`).
- **Defaults are deliberate**: trains on `anne_log_synthetic.db` (not the real log) — override with `--db`. `train_and_evaluate` raises Hebrew ValueError on an empty or single-class log. Partial records are fine at predict time (missing numerics → imputer, missing topic → "unknown").
- Offline checks (slide 17): leakage/classification guard, deterministic train on fresh synthetic data (fixed seeds) with sane metrics, joblib save/load round-trip (loaded prediction == in-memory prediction), missing-model raises `FileNotFoundError`, valid 0–1 probabilities incl. partial records and `predict_frame` batches, dashboard prediction-tab wiring, and two AppTest runs of the app — with a trained model (`ANNE_ML_MODEL` → temp bundle) and without one.

### Frontend wrapper (`server/` + `web/`)

FastAPI wrapper around the existing pipeline — `python -m uvicorn server.app:app --port 8000`. **Wrapper only: the single call inward is `ChatSession.run_turn`.** No agent/RAG logic lives here.

- **Endpoints**: `POST /api/chat/stream` (SSE, what the browser uses) and `POST /api/chat` (single JSON reply — the browser's fallback and the path the offline suite drives); both are paid. `GET /api/welcome` (fixed text, free), `GET /api/demo/scenarios` (the demo catalog, free — deliberately **not** behind the admin gate, because the runner lives on the un-gated chat page and the content is demo text anyone could type), `GET /api/health`, `GET /admin` (page), and `/api/admin/*` (all free). Documents have three routes: `/api/admin/doc/{key}/view` (parsed JSON for the viewer), `/api/admin/doc/{key}/page` (branded HTML for the iframe kinds) and `/api/admin/doc/{key}` (the original file — the download fallback). Static mounts (`/assets`, `/illustrations`, `/`) are registered **after** the routes — Starlette matches in order.
- **SSE shape** (`chat_stream`): `stage` (with a Hebrew label from `_STAGE_LABELS_HE`) → `delta`* → `done` (the full payload; the reply there is the source of truth). `run_turn` executes in a worker thread and pushes progress through a `queue`, so a disconnected browser still lets the turn finish and be logged. Streamed text passes `_StreamSourceFilter`, a line-buffered version of `_strip_source_lines` that withholds only as much as needed to tell whether the current line is a `מקור:` line — otherwise the source line would flash in the stream and vanish at `done`. The client never re-runs a turn that already started: `streamTurn` returns `unsupported` (fall back to `/api/chat`) vs `broken` (show an error, don't pay twice).
- **Conversation continuity**: the browser mints a random `user_id` in `localStorage`; the server maps `user_id → live ChatSession` (LRU, 100) with a per-session lock (`run_turn` isn't concurrency-safe within one conversation). The `user_id` is never written to the log — `storage/`'s structural privacy is preserved; the log still groups turns by the `ChatSession`'s own `session_id`.
- **Startup warm-up thread** (`_warm_start`): imports `crew.pipeline` *and* calls `crew.tools.warm_up_rag()`. The second part matters — measured in `anne_log.db`, the first turn of a cold process paid **+25 to +50s inside the consult stage** waiting for the e5 embedder (~2GB) to load under the RAG lock (turn 1: 34s consult; a fresh server run: 57s). Best-effort: a missing API key or a broken index never breaks static serving.
- **Source shown once** (slide 15): `_strip_source_lines` removes `מקור:`/`מקורות:` lines (incl. bullet/bold variants) from the reply body before it reaches the browser; the UI renders the source line once, from the `sources` field that the schema validator already checked against `data/`. Display-only — the compose instruction and the consult itself are untouched.
- **Admin area** (`web/admin.html` + `admin.css` + `admin.js`, one page, three views — login / hub / document viewer): access control is **a single admin user whose credentials live in `.env`, outside version control — a deliberate design decision matched to the system's scope** (one actual user, so no user-management layer is needed; it is not an interim step toward a cloud auth provider). The user is checked server-side against those two variables and gets an in-memory token (8h TTL, `sessionStorage` in the browser). **The credentials live in the environment, never in code**: `ADMIN_EMAIL` / `ADMIN_PASSWORD`, loaded from `.env` by a `load_dotenv()` at import and read *per request* through `admin_email()`/`admin_password()` — module constants would have frozen a stale value and created a second source of truth. `.env.example` carries placeholders only, because it is committed. **There is no default that permits login**: `admin_credentials_configured()` gates the endpoint before any comparison, and missing variables return **503 with "לא הוגדרו פרטי כניסה"**, not 401 — the person typing did nothing wrong, and the difference between "wrong password" and "no password configured" is exactly what saves the quarter hour. That gate is load-bearing rather than cosmetic: `compare_digest(b"", b"")` is `True`, so without it empty fields against unset variables would have opened the door to anyone. The client has its own `503` branch that surfaces the server's Hebrew message instead of "wrong credentials". Credentials are normalized before comparison (`_normalize_credential`, `_credentials_match`) and compared **as bytes**: `secrets.compare_digest` on *str* raises `TypeError` on any non-ASCII character, and in an RTL page an invisible bidi mark (RLM/LRM, which `str.strip()` does not remove) rides along on a paste — that turned correct credentials into a 500 that the browser rendered as "wrong email or password". Login failure is now always 401, never 500, and the client shows a distinct message per status so a real error can't masquerade as bad credentials again. The email field has **no placeholder address** (`dir="ltr"`, `autocapitalize="none"` to keep bidi marks out of the value). Matching that same scope, the admin area guards nothing sensitive either: `documents.DOCUMENTS` is a **closed dict** of project documents read from their real locations (`README.md`, `CLAUDE.md` and `llm_requirements.txt` from the root, the rest from `docs/`/`data/`/`illustrations/`) — no `.env`, no `*.db`. The key from the browser is a dict key, never a path, so path traversal has nothing to traverse; the token travels in the query string because the viewer's iframe and the download link cannot send headers (acceptable at this scope, where the token grants access to project documents only). An offline check walks every `source` *and* `download_path` in the registry and fails on any `.env`/`.db`.
- **View switching** (`web/admin.js :: showView`): the login card, the admin hub and the document viewer are three sections in one page, toggled by the HTML `hidden` attribute. `admin.css` therefore **must** keep `[hidden] { display: none !important; }` — an attribute selector has the same specificity as a class, and on a tie the author sheet beats the UA sheet, so `.login-view/.admin-view/.error-strip { display: flex }` silently defeated `hidden`: a successful login left the user staring at the login screen (the admin hub rendered *below the fold*) and the red error strip showed from first paint. It is nevertheless MIT: the repo's root LICENSE at that exact tag is the full MIT text ("Copyright (c) 2025 crewAI, Inc.", byte-identical to `main`), and the README shipped *inside* the wheel declares MIT with a badge. So the table records that one verified fact — and three rules stop it from becoming a place where wrong facts hide: (1) **published metadata always wins** — the override only fires when classification came out `unknown`, so a future version declaring GPL is flagged as strong copyleft (mutation-tested); (2) no entry without `license` + `evidence_he` + `source_url`, enforced by an offline check; (3) the UI marks the row "אומת ידנית" with a dashed border and a link to the verified file, and an `ok` verdict that leans on a manual check must say so in words. The sticky bar shows "תור N מתוך M", a progress fill, and a stop button. **Stop halts the scenario, not the turn in flight** — a turn already running has been paid for and will finish and be logged, so the button says so ("עוצר בתום התור הנוכחי…").
  - **The sticky bar exists only while a scenario runs.** `showBar`/`hideBar` are the only two places that touch its visibility, the hide sits in a `finally` (so scenario end, a deliberate stop, a turn that timed out and an unexpected throw all close it), and the mechanism is the HTML `hidden` attribute — which means `web/style.css` **must** keep `[hidden] { display: none !important; }`, exactly like `admin.css`. Without it `.demo-bar { display: flex }` wins the specificity tie against the UA sheet and the bar is visible *always*: an empty strip under the header in a normal conversation, and 49px of dead space stolen from the chat after a scenario ends (measured in headless Chrome: `display:flex`/`offsetHeight=49` vs `none`/`0`; the chat top moved 89px → 40px once fixed). An offline check asserts the default-hidden attribute, the override rule, the two-call-sites rule and the `finally`.
  - **`?demo=<id>` is stripped from the URL immediately** (`history.replaceState`) — a refresh must never silently re-run a paid scenario.
  - **The end card summarises what was demonstrated** from the turn payloads, not from the scenario file: which doctors handled it (topic → doctor via the JSON's `doctors` map, plus Dexter when an emergency fired), which tools ran, which illustrations appeared, whether the safety gate stopped the conversation (with its red flags), turns completed and total LLM calls. This is why `_turn_payload` now also carries `tool_usage` (zero-count tools filtered out) and `llm_calls` — both already existed on `TurnResult`; nothing new is computed.
- **Design**: derived from the project's Stitch design system ("Warm Clinical Care", project `3408855817725362904`) and its generated sign-in screen, but hand-translated to plain CSS over `/assets/colors.css` — no Tailwind CDN, no icon font (inline SVG), consistent with `web/style.css`. Branding uses `assets/Logo.png` (mark) and `assets/Logo_2.png` (decorative figure on the login screen).

### Computer-vision layer (`vision/`) — an image that enriches the anamnesis

The user attaches a photo to a message and the system derives **context for the questioning, never a diagnosis**. No new agent and no new role: the output is injected into the existing prompts exactly like the time and weather context, and the decisions stay where they were — with the specialist and with Dr. Dexter.

- **Pillow + numpy, deliberately no OpenCV** — blur, exposure and colour ratios are arithmetic on the pixel matrix; OpenCV would add ~60MB and a cross-platform binary dependency for that. `numpy<2` is untouched (Pillow has no numpy pin).
- **Three layers + a security gate**, one file each: `ingest.py` (format **by content** — a text file renamed `.jpg` is rejected; JPEG/PNG/WebP only; 6MB / 40MP ceilings checked before decode; **EXIF stripped** — GPS and device model — before any processing, with `exif_transpose` first so a rotation recorded in EXIF is baked into the pixels; downscale to ≤1024px), `quality.py` (א — usable?), `features.py` (ב — deterministic measurements), `describe.py` (ג — the vision model), plus `scope.py` and `analyze.py` (the orchestrator returning `ImageAnalysis.context_he`).
- **Blur needs two metrics, not one.** Laplacian variance averages the whole frame, so smooth skin photographed well scores as low as a smeared photo (measured on synthetic images: sharp skin 64, blurred skin 0.1). `edge_strength` — the 99.5th percentile of |Laplacian| — asks "is there a sharp transition *somewhere*", and there the separation is clean (37–547 vs 1.4–6.3). An image is called blurry only when **both** are low.
- **Redness is measured relative to the image itself.** An absolute "R dominates G and B" threshold marks 67% of a plain warm-skin photo — technically true, useless for triage. The reported `red_ratio` counts pixels whose redness exceeds that image's own median by a margin, so healthy skin gives ~0% and a wound stands out; `red_ratio_absolute` is kept beside it, and a full-frame red close-up is described as "uniform warm tone, no standout area" rather than as a finding. An offline check measures a synthetic spot of known size (2.19% and 6.25%) to ±0.2%.
- **The vision model describes, never diagnoses.** `SYSTEM_PROMPT_HE` forbids diagnosis, naming a disease, recommending treatment and grading severity; it asks for 2–4 plain-Hebrew sentences about body part, relative size, colour, edges, discharge and surrounding skin. `detail: "low"` (see the cost note in README). No key / no network / an unusable image → `DescriptionResult(ok=False)` and nothing more: the deterministic measurements still ship and the turn continues. `ANNE_VISION=0` disables the call entirely; `ANNE_VISION_MODEL` overrides the model.
- **The image never widens Anne's remit.** `scope.py` scans the description against a closed lexicon (mole, eye, nail, tooth, unidentified rash…) and, on a hit, the injected context carries an explicit *do not treat — say it's out of scope and recommend a doctor* instruction. Whole-token matching with one-letter prefix stripping (ה/ב/ל/ו/כ/ש but **not** מ or י, so "מעין" never reads as "עין" and "ישן" never as "שן"); bare "שיער" was dropped from the lexicon because a legitimate wound description may mention hair.
- **Wiring**: `run_turn(..., image_context=)` injects the block into all four stages (gate, triage, both consult paths, compose) with `NO_IMAGE_HE = "לא צורפה תמונה"` as the explicit default. `crew/` does **not** import `vision/` (no Pillow dependency in the agent layer) — the server, which received the upload, does the analysis and passes the text. Dexter's backstory gains authority to escalate on the description (spreading infection, deep or gaping wound, extensive burn) *even if the user never said it*, with an explicit caution not to escalate on a blurry photo or redness alone; Anne's compose rule requires her to say the image was taken into account (transparency), and her triage rule says an out-of-scope image means `reply`, not `consult`.
- **Privacy**: the bytes live in the request's memory only — nothing is written to disk in any vision module (an offline check greps for bare `open(`, `save(<path>)`, `tempfile`, `write_bytes`…, allowing only `save(buffer)` into `BytesIO`), and the log records **one boolean and nothing else** — `image_attached` (0/1), no dimensions, no measurements, no description. From the value `1` you cannot learn anything about the photo or about who took it, which is the same reduction the schema already applies to message text (lengths only). `TurnResult.image_used` is what feeds it.
- **Two image step types, both through the user's own upload path.** `docs/demo_scenarios.json` allows a `messages` entry to be an object; the loader emits `messages` (text only, unchanged contract) **and** `steps` (the full sequence) from that same array, so there is still one source:
  - `{"type": "attach_image", "image_path": …, "message_he": …}` — **the default now**: `web/demo.js` fetches the image, wraps it in a `File`, writes it into the real `#image-input` via `DataTransfer` and dispatches `change`, which runs the *same* `attachFile()` a human triggers. From there it is identical to a real upload: same browser-side validation, same base64 in the same request, same content-sniffing / EXIF-stripping / downscaling on the server. The run therefore goes end-to-end with **no intervention** — verified in headless Chrome: two turns sent, the image present only on the turn that declares it, `demo:true` intact, thumbnail in the user bubble, no upload card shown.
  - `{"type": "await_image", …}` — still supported, for showing a real upload: it pauses and shows a card whose button clicks the same `#image-input` (a programmatic click needs a user gesture, so the lecturer's click is the gesture), then waits for the `anne:image-attached` event `app.js` fires.
  - **The path is validated server-side** (`_demo_image_url`): relative only, under `assets/`, a supported image suffix, and the file must exist — otherwise the step degrades to a plain message so a live demo never stalls on a missing asset. The client never assembles a path; it receives `image_url`.
  - **The one image in the repo** is `assets/demo/demo_hand_abrasion.jpg`, AI-generated for this project (no third-party rights, like the illustrations) — and because the licenses page claims to cover *all* content assets, it is declared there too (`build_demo_image_rights`, counted live from the directory). An offline check runs the file through the real ingest path (content type, size, EXIF removal) **without any vision-model call**, so a broken demo asset fails the suite instead of failing in front of an audience.

### Personal credit (`credit.py` + `web/credit.js`) — one source, every surface

The line "נבנה על ידי **מאור דהן** במסגרת קורס AI מטעם בית הספר למנהל עסקים של האוניברסיטה העברית" appears on **every** screen: the chat, all three admin views (login, hub, and the document viewer — which is how the demo-scenarios screen, the gallery and the licenses view get it), the branded document pages served into the iframe, the public `/accessibility` statement, and both Streamlit apps.

- **`credit.py` is the source of truth** — text, URLs, Hebrew aria labels, the tap-target size, the inline SVG paths, and the CSS. Python consumers import it (`server/documents.py :: _doc_page`, `dashboard/ui.py :: sidebar_footer`, so one line covers both apps).
- **`web/credit.js` mirrors it** for one technical reason: a static HTML page cannot read a Python module, and reading a JSON would add a network request — the credit must work offline. So the values are written there too, and **an offline check compares all nine fields character-for-character** (text, both URLs, both aria labels, both SVG paths, the tap target). Any drift fails the suite, which is what keeps it a single source in practice. Mount points are `<div data-anne-credit>` — the script fills every one on the page and injects its style block once (no extra stylesheet, no extra request).
- **Security**: all three links carry `target="_blank"` **and** `rel="noopener noreferrer"` — without `noopener` the opened page gets `window.opener` and can navigate ours away.
- **Accessibility**: each icon link has a Hebrew `aria-label` ("פרופיל LinkedIn של מאור דהן"), the SVG inside is `aria-hidden`/`focusable="false"` so the name comes from the link and is not read twice, the hit area is **44×44** (`min-width`/`min-height`, verified as 44×44 in headless Chrome while the glyph stays 17px), and `:focus-visible` is defined in the credit's own CSS so focus is visible even on the document pages, which do not load `a11y.css`.
- **Print**: the credit lives *inside* the branded document page (not in the frame around it), because printing a document prints the iframe content only — and its CSS carries an `@media print` block that keeps it visible in black.
- **Offline by construction**: inline SVG, no CDN, no icon font, no `fetch`, no `src=` anywhere in the credit markup.

### Accessibility (`web/a11y.*`) — target: WCAG 2.1 level AA

The target is **AA only** (not AAA) — the common denominator of **SI 5568 part 1** (Sept 2023, which is WCAG **2.0** plus Israeli national changes) and **EN 301 549** (WCAG 2.1 AA). WCAG 2.1 is a superset of 2.0, so working to 2.1 AA covers both. Read from the standard itself, not from memory — two Israeli deviations actually matter here: **2.4.10 Section Headings** is raised from AAA to **AA** (headings must be real `h` tags), and **3.1.2 Language of Parts** **does not apply** (the standard's own reasoning: UTF-8 lets the screen reader detect foreign words), which is why there are deliberately no `lang` wrappers around Latin terms. The media criteria (1.2.x) are moot — there is no audio or video.

- **The chat's live regions are the part that earns its keep**, and they are three separate things by design: `#chat` is `role="log"` + `aria-live="polite"` + `aria-relevant="additions"` (a complete message announces when it lands); `#chat-status` is `role="status"` for the stage labels ("מתייעצת עם הצוות הרפואי…"); `#chat-alert` is `role="alert"` — assertive — for Dexter's emergency verdict, which interrupts whatever is being read. Both announcer elements exist in the HTML from first paint, because a live region created *together with* its content is not announced.
  - **Streaming must not announce per delta.** While deltas arrive the bubble carries `aria-hidden="true"`; on `done` the attribute is removed and the row is **re-appended** to the log — a re-insertion is an "addition" for `aria-relevant`, so the complete answer is announced exactly once, with no duplicated mirror text. The typing indicator itself is `aria-hidden` (it is an animation; its meaning lives in the status region). Verified in headless Chrome across the stream lifecycle: `aria-hidden=true` at 520ms and 700ms (mid-stream), absent at 1100ms (after `done`).
  - The emergency path suppresses the log's live region for one tick (`aria-live="off"` → back to `polite`) so the assertive alert isn't read twice, and the alert text is prefixed with the hotline ("מצב חירום — פנו לעזרה מיידית, חייגו 101").
- **Palette contrast was measured and fixed at the token level**, so ~50 usages moved at once: `--text-muted` 4.25 → 5.16, `--link` 3.72 → 5.33, and the primary button (white text on `--coral-400`) 2.48 → 5.33 via a deeper `--btn-primary: #B34A32`. New tokens: `--text-accent` (coral for *text*, since `--coral-600` at 3.72 is background-only), `--border-control` (#A18974, 3.31:1 — a form control's border is often the only thing identifying it, 1.4.11) and `--focus-ring`. An offline check scans every `color: var(--…)` in the three stylesheets against both backgrounds it can sit on and fails under 4.5:1 — the fix cannot silently erode. `html.a11y-contrast` overrides only the semantic tokens, which is why high-contrast mode works across both pages without touching a single component.
- **The accessibility panel** (`a11y.js`, shared by both pages) is an APG **disclosure**, not a dialog: a fixed corner button with `aria-expanded`/`aria-controls`, content toggled by the `hidden` attribute, Escape closes and returns focus. Four preferences — text size (100–160%, via `--a11y-text-scale` on the root, which works because every size in the project is in `rem`), high contrast, reduced motion, strong focus ring — persisted in `localStorage` and applied as classes on `<html>`. Two things that were caught in review and must stay: the script is loaded **synchronously in `<head>`** (with `defer` the page painted once with defaults and then flipped — a flash that hurts exactly the users who chose those settings), and the widget is inserted **after** the skip link, not at the top of `<body>`, so the skip link stays the first tab stop. The panel's title is a `<span>`, not an `<h2>`: the widget sits before the `<h1>` in the DOM, and a heading there inverted the document's heading order.
- **Illustration alt text** is built from the name *and* the demonstrated steps (`anneA11y.illustrationAlt`, one function in `a11y.js` used by both the chat bubbles and the admin gallery — an offline check fails if either page re-defines it). "איור" is not a description. Avatars and the decorative figure are `alt=""`, and the speaker is carried by a `.sr-only` "אן: " / "אני: " prefix inside each bubble so the log makes sense when read linearly.
- **The demo runner's progress** is a real `role="progressbar"` with `aria-valuenow` **and** `aria-valuetext` ("תור 2 מתוך 4" — a percentage alone doesn't tell you which turn you're on), and its state line is a `role="status"`.
- **`docs/accessibility.md` is served publicly at `/accessibility`** (no token — a statement only an admin can read is worthless) *and* appears in the admin viewer as the `markdown` kind, from the same live file. It is deliberately worded as a **statement of intent, not a legal conformance claim** ("הצהרת שאיפה"), because this is an educational project — and it lists what is *not* covered (no real screen-reader user testing, the Streamlit apps, the binary documents). An offline check enforces both the aspiration wording and the absence of a conformance claim.
- **Offline checks** (group "נגישות — WCAG 2.1 רמת AA", 8 checks): landmarks + `lang`/`dir` + heading order with no level skips (and one `h1` per *view* in the admin page, which is legal because the other views are `hidden` — same rule that lets three `<main>` elements coexist there); `alt` on every HTML `<img>` and on every JS-built image; an accessible name on every icon button and a linked `<label>` on every field; the three live regions plus the progressbar; the contrast scan; keyboard (skip link first, no positive `tabindex`, `:focus-visible` present); the panel's ARIA + persistence + Escape; and the statement's wording and routes. What cannot be derived from source — real tab order, panel behavior, `aria-hidden` during streaming, no horizontal scroll at a true 320px viewport (measured inside a 320px `<iframe>`, since headless Chrome clamps the window to ~500px) — was verified by rendering in headless Chrome.
- Offline checks (slide 18, plan 18): login success/failure, every `/api/admin/*` blocked without a valid token, closed-list-only serving (unknown key and `../` → 404, no `.env`/`.db` across every `source` *and* `download_path`), inline vs attachment disposition, logout invalidation, `/admin` assets served, chat-header entry point present; **plus one check per renderer** covering valid parse / missing file / empty file, the server↔client renderer wiring, and the live-source guarantee; **plus the demo runner** — the scenario catalog (5 scenarios, 3–4 turns, unique ids, natural openers, all topics + the safety path covered), its failure modes (missing file / broken JSON / empty list / a scenario with no id or no messages, which is skipped rather than fatal), the admin-button → runner wiring, the "ordinary user input" guarantee, and the `tool_usage`/`llm_calls` fields the end card depends on. Plus (slide 15) source-line stripping and a stubbed `/api/chat` turn proving body-without-`מקור:` + populated `sources`. All in-process via `fastapi.testclient` — no port, no crewai import, no LLM. The rendered result itself was verified in headless Chrome against a stubbed `fetch` (no server): the documents open, view switching computes correctly, and the three bespoke renderers produce 19 plan cards / 25 source cards / 20 illustration tiles.

### Data layout

`data/` has one subdirectory per topic: `wounds`, `anxiety`, `dehydration`, `cold`. Each `.md` file: a `# ` title, four `## ` sections, then a `---` footer containing a `מקור:` line. Adding a topic = adding a subdirectory; its folder name becomes the `topic` automatically on the next `build_index.py`.

`data/emergency_locations.json` is the one file under `data/` that is **not** RAG input — it is never chunked or embedded (chunking only walks `data/<topic>/*.md`). It is the emergency-destination store read by `crew/emergency_referral.py`; edit it by hand, then run `python geocode_emergency_locations.py` if you added records.

`chroma_db/` is generated and not under version control — rebuild it rather than editing it.

## Non-code assets

`assets/` (logo, avatar, color palette), `illustrations/`, and `docs/` (presentation — `anne_presentation.html`, progress board, test plan, storyboard, project summary docs) are project deliverables, not part of the runtime pipeline. The one exception is `docs/demo_scenarios.json`, which *is* runtime input: it is the single source of the admin demo runner's scenarios (see the frontend section). Editing it changes the demo; there is no copy in code. They are also the *content* of the admin document viewer (`server/documents.py`), which reads them live — editing a file under `docs/` changes what the admin area shows on the next open, with no code change.
